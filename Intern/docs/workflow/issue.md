# Issue 跟踪规范

项目开发追踪以 [当前 GitHub 仓库的 Issues](https://github.com/flyingEirc/IotProject/issues) 为主。新增功能、修改功能、问题修复和方案调整都必须关联对应 Issue，持续维护分析、执行进展和验收结果。本地任务清单、调研笔记和 PR 作为辅助材料，链接回 Issue，不替代主要记录。

## 必须包含的五部分

按“背景 → 功能 → 步骤 → 验收 → 交付”组织正文；开始时尚未获得的分析、结果或产物标记待完成，不把推测写成结论。

| 部分 | 要求 |
| --- | --- |
| 1. 背景 | 描述引入或修改的原因、来源与当前状态。若由前期 Issue 或提交引出，直接指向目标 Issue 与提交链接/完整 SHA，说明触发条件和影响；原因未确认时标为待定位。保留调查证据、原因/约束、方案比较与结论。 |
| 2. 功能 | 写清新增或修改什么、预期行为、影响范围和明确不包含的内容。关联适用路线文档、已定决策和 CLI/Web/base 接口影响。 |
| 3. 步骤 | 根据分析列出实现功能所需的执行步骤、依赖和进度，用可勾选条目持续更新。方案改变时记录原因、决策与调整后的步骤。 |
| 4. 验收 | 分步骤定义可观察结果、验证方式、环境/版本和通过条件；执行后逐项填写结果及证据。不能只写“代码完成”“端口连通”或“退出码为零”。 |
| 5. 交付 | 描述最终产物与实际效果，链接提交、PR、文档、迁移或制品，附验收结论及未完成项。记录提交时使用的 **agent harness 和模型名称**。涉及前端 UI/UX 时，必须记录交付产物的**截图或 MP4 视频**。 |

## 执行与拆分

1. 开始前查找现有对应 Issue，避免重复。记录背景、分析、功能、步骤和验收计划，再实施；排障中的新发现回填背景与步骤。
2. 涉及整体方案、范围、技术选型或验收标准时，必须在 Issue 记录分析和明确结论，并同步 [roadmap](../README.md) 中对应路线；未经决策不得静默更换。
3. 一个 Issue 出现多个可独立交付的目标时，必须拆成多个 sub-issue 分别分析、实施与验收。父 Issue 记录总体背景、目标、拆分关系、依赖与整体验收；每个子 Issue 同样包含五部分。
4. 按 [PR 与提交规范](pr.md) 关联分支、提交与 PR。跨 CLI、Web、base 的工作在父/子 Issue 记录接口归属和合入依赖。
5. 关闭前逐项记录验收结果、最终交付物与剩余限制；未满足标准不得标记完成。父 Issue 还须核对子任务状态和整体交付结果。

## 交付证据

- 明确区分设计完成、代码完成、原生进程验证和真实容器 CI 通过；结果绑定源码/制品版本及实际运行证据，遵循 [质量规范](../guide/quality.md)。本轮未重跑的历史结果必须标注来源和时间。
- 每个交付提交记录 harness（如 Codex 桌面应用、Claude Code）与会话实际可确认的模型名称；多人或多个 agent 参与时按提交分别对应。精确型号不可获取时写明“未暴露”，不得猜测；人工提交写“人工 / 不适用”。
- UI/UX 截图或 MP4 必须来自实际交付版本，链接可访问的 Issue/PR 附件或版本化证据路径，并注明提交 SHA、页面/关键状态、操作步骤和对应验收项。截图覆盖静态效果，交互或动态效果可用 MP4 展示；mockup 不能冒充已实现界面。
- 证据先脱敏，禁止暴露密码、密钥、token、完整 DSN 或用户敏感数据。纯后端、CLI 或文档交付可明确填写“UI/UX 证据：不适用（原因）”；实际涉及 UI/UX 的任务不得省略。

## GitHub 模板入口

在 GitHub 新建 Issue 时选择“功能新增、修改或问题修复”，即可带入下方五段正文。模板文件位于**实际 Git 根目录**的 [.github/ISSUE_TEMPLATE/change.md](../../../.github/ISSUE_TEMPLATE/change.md)，对应本项目目录的 `../.github/ISSUE_TEMPLATE/change.md`。

模板正文与本页“正文模板”保持一致；修改其中一处时同步另一处。模板进入仓库默认分支 `main` 后才会在 GitHub 新建界面出现，本地新增或仅推送其他分支不代表已生效。规则依据见 [GitHub 模板说明](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/about-issue-and-pull-request-templates)。此入口交付追踪 [#12](https://github.com/flyingEirc/IotProject/issues/12)。
